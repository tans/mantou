# 抖音视频发布与核验

用户要求发布课本教学视频，或检查已提交作品状态时使用。制作和修改课程视频按 `textbook-video-production` 技能完成。

## 发布前

1. 阅读仓库 `AGENTS.md` 和目标课次 README，确认最终视频文件、标题、文案、账号、可见范围和发布时间。沿用用户明确指定的值；缺项且会改变发布内容时再向用户询问。
2. 发布操作必须由当前请求明确授权。检查状态、审核中等待、公开页验证或仅准备素材都不构成发布授权。
   对短集按[导演流程](../../../projects/DIRECTOR_WORKFLOW.md)运行 `review_short_series.py --require-publishable`，指定当前配置、bindings、集数和人工复核文件；仅返回0时继续。pending/fail/过期SHA先修订或完成带声音复核，再复跑。历史发布不因新增门禁改写为已验收。
3. 使用 BrowserOS Neo 的抖音创作者中心。确认登录账号是目标账号，并按作品管理页面的当前流程操作；需要登录、验证码或人工确认时暂停并请求用户处理。
4. 选取 README 指定的最终视频，核对标题、文案、公开范围及立即/定时发布选项。最终提交前再核对一次这些值；只在当前请求已授权时点击发布。
   有独立封面时使用QA指定的`cover.path`，核对实际文件与`cover_sha256`一致，`cover_visual=pass`；平台裁切后复查横竖封面的文字/人物安全区并记录。改选其它封面时先归档、复核并更新QA，再提交。

## 核验状态

提交后在创作者中心“作品管理”中找到标题完全匹配的作品并读取平台状态。提交成功提示本身不证明已发布。

- **审核中：**记录当前状态；不编辑、删除或重复提交。仅在用户要求持续跟进时安排后续检查。
- **审核未通过：**记录平台显示的原因并报告；不创建重复作品。等待用户提出修订或重新发布要求。
- **已发布：**从作品卡片或公开主页取得作品链接，在 BrowserOS Neo 打开该链接，核对页面标题和视频内容已加载。记录作品 ID、公开 URL、创作者中心状态、发布时间和实际看到的核验证据。只有完整观看并听完后才记录全片视听通过。
- **状态不明或链接无法打开：**保留为未确认，记录页面提示或阻塞，不推断为已发布，也不重复提交。

## 课次记录与收尾

在课次 README 的“抖音发布记录”追加或更新标题、作品 ID、发布时间、审核/发布状态、公开 URL，以及 BrowserOS Neo 实际核验到的证据。持续跟进时保留状态变化历史；不要覆盖此前的失败或审核记录。

完成后在 `main` 上提交本次 README 和技能文档，并在有远端时推送。只暂存本任务改动的文件；保留其它未提交工作。将创作者中心和公开视频页留在 BrowserOS Neo 中，供用户查看。
