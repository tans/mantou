# 小学教材视频批量制作指南

本指南把多课制作组织成一个可追踪批次，并规定人工修订后复用未变化素材的办法。单课内容与证据仍以各自课次目录为准；本指南管理批次范围、统一规格、执行顺序和增量重跑。完整素材产物与质量要求见[教材动画制作技能](../.agents/skills/textbook-video-production/SKILL.md)和[教材动画生产标准](grade-4-english-term-1/PRODUCTION_STANDARD.md)。

## 1. 批次边界与目录

一个批次通常共享出版社/版次、制作规格、视觉基调或交付时段。不同册次或教材版本可放入同一批次，但每课必须独立核实教材来源、脚本和教学目标；共享角色、音色或视觉配置须以稳定 ID 引用，不把一课的对白复制到另一课。

```text
projects/batches/<batch-id>/
  batch.yaml          批次范围、共享默认值、预算与课次清单
  batch-board.md      批次队列、当前阶段、阻塞与交付概况
projects/<教材与年级>/<课次>/
  README.md           该课权威状态与证据索引
  script/ characters/ storyboards/ audio/ shots/ edit/ renders/
```

`batch.yaml` 保存批次计划及每课路径/特殊范围；`batch-board.md` 用于浏览队列，不替代课次 README、素材 manifest 或 sidecar 中的详细状态和证据。课程的教材依据、行级台词、角色、任务参数、输出和验收始终落在该课目录。根素材索引增加批次入口，不把大体积视频拷贝到批次目录。

从[批次看板模板](BATCH_BOARD_TEMPLATE.md)创建 `batch-board.md`。批次摘要记录总课数、完成数、待人工检查数、阻塞数及总费用；任务 ID、素材哈希、源文件路径等证据只写在课次文件中。

## 2. 批次清单

新建批次时复制[批次清单模板](BATCH_MANIFEST_TEMPLATE.yaml)到 `projects/batches/<batch-id>/batch.yaml`。`batch-id` 使用小写、日期或教材简称，保持稳定。只记录非机密配置，禁止放 API key、Cookie 或私有下载令牌。

模板字段的用途如下：

| 字段 | 要求 |
| --- | --- |
| `curriculum` | 按教材版权页填出版社、系列、年级、册次、版次/年份；各课仍须逐课核验具体来源和页码。 |
| `shared_defaults` | 只放确实共享的 voice library、已复核的视觉 profile ID、输出预设和帧率；单课差异放课程条目的 `overrides`。 |
| `generation` | 填允许使用的 provider/model 和最大并发数；允许列表为空表示还没有选择生成服务，不能启动供应商任务。 |
| `budget` | `max_batch_spend`、`max_per_lesson` 须在运行供应商任务前确定；费用上限为 `null` 表示尚未授权计费生成。 |
| `lessons` | 每课登记稳定 `lesson_id`、唯一目录路径、具体制作范围和可选覆盖值；不得把几课内容混成一个脚本。 |

运行批次前检查路径唯一、教材来源可定位、脚本范围不重叠或明确标记重叠、输出标准可执行、总预算及单课预算合理。模板中的示例占位值必须替换后再执行。

## 3. 状态与可编辑交接

批次看板按一行一课记录 `lesson_id | 路径 | 当前阶段 | 状态 | 下一动作/阻塞 | 已用/预算 | README`。状态统一为：

- `待开始`：尚未进入当前阶段。
- `进行中`：正在整理或执行，记录执行者/脚本/开始时间。
- `待人工检查`：机器步骤已结束，等待有针对性的内容或视听检查。
- `阻塞`：缺少教材证据、凭据、预算、服务可用性或不可替代输入；写明恢复条件。
- `失败可恢复`：任务可用原 task/job ID 继续查询或下载。
- `完成`：阶段完成条件有可检查证据。
- `已失效`：上游内容或参数变化，旧产物保留但不能作为当前版本输入。

允许批次内各课处在不同阶段。单课 README 是具体阶段状态和人工结论的权威记录；批次看板只同步概况与下一动作。人工修订直接改对应的规范文件（例如 `dialogue-vN.md`、角色 Bible、Storyboard、`prompt-vN.txt`、SRT 或 `assembly-vN.md`），递增版本并保留旧稿。聊天意见、模型输出或看板摘要不能替代文件修改。

每个节点的制作记录至少列出：节点 ID/类型、输入路径及版本、输入 SHA-256、配置或提示词版本、输出路径及版本、输出 SHA-256、工具/供应商/模型、task/job ID（若有）、费用（未知则写未知）、机器探测、人工检查、状态和失效原因。哈希证明使用了哪个文件；哈希变化本身不代表语义变化，按下表判断真正的失效范围。

## 4. 批次执行顺序

按批次分层推进，先统一修正会影响多课的规则，再启动昂贵生成。教材核对仍按课逐页完成；批次统一的是模板和配置，不是把教材结论批量复制。

1. **计划**：检查仓库说明和现有课次，建立清单/看板；登记预算、输出规格、预计共享角色/视觉/voice profile。检查课次目录及现有稿，续做时从其未完成或已失效节点继续。
2. **核实来源**：每课核对版次、单元、印刷/PDF 页码、官方或第三方来源，并记录缺项。无法核实的内容标 `UNRESOLVED`，只阻塞依赖它的行和镜头。
3. **批量定稿可编辑素材**：逐课生成规范脚本、角色 Bible、Storyboard、每镜头提示词和字幕草稿；共享角色/风格配置先固定 profile ID。完成人工校订后，把定稿文件及版本登记入课次 README。没有待解决的内容依赖才进入相应生成阶段。
4. **先做代表性样片**：按已核实内容挑一课/一镜，执行 TTS、镜头和合成样片，抽查角色/风格、可读性、模型参数和成本。发现共性问题时先修共享 profile/模板，再重跑样片；确认批次规格后再批量生成，避免同一缺陷扩散。
5. **批量生成**：按阶段推进独立课程/镜头；以 `scripts/generate_tts.py` 处理行级语音，以 `scripts/generate_video.py` 处理供应商镜头，以 `scripts/compose_vertical_lesson.py` 处理固定竖屏合成。使用各自技能的 dry-run、状态轮询和恢复方式。每个输出单独保存、探测并登记，不能因某课阻塞而重做其它课。
6. **人工复核与局部返修**：先看片/试听需要人工判断的节点；将问题定位到行 ID、shot ID、字幕 cue 或合成参数。修订规范输入、记录失效后，只运行失效节点和其下游。
7. **交付批次**：逐课完成全片播放/试听和素材索引更新；汇总课程数、完成/阻塞数、成本、交付路径和未验收项。任何未完整视听的内容仍标为预览/待验收。

## 5. 依赖关系与局部重生成

```text
教材来源/页码
  └─ 对话脚本与说话人
      ├─ 角色 Bible / voice profile ─ TTS（按行）─ 混音 ─ 字幕时间轴
      └─ Storyboard ─ 提示词/参考图（按镜头）─ 视频镜头
                                       TTS + 镜头 + 字幕
                                                   └─ 横屏合成
                                                        └─ 竖屏布局合成
```

仅在依赖边向下重跑；保留并复用未受影响、版本/哈希/参数吻合且质量检查通过的节点。对于供应商输出，复用键至少包含 provider、model、提示词与参考素材哈希、时长、尺寸/画幅、seed/steps（若可用）、音频设置以及脚本适配器版本。任何关键参数变化都不能把旧输出伪装成新输出。

| 修改内容 | 失效并重做 | 保留/复用 |
| --- | --- | --- |
| 教材版本、页码、原文或教学范围 | 受影响的脚本行；对应角色/Storyboard/提示词、TTS、字幕及成片；若共享教材/课程范围都变则覆盖全批次 | 其它课次未引用的教材、稿件和已验收素材 |
| 单条英文脚本、说话人或行顺序 | 此行及相关说话人映射、依赖它的 shot、该行 TTS/混音段、对应字幕 cue/时间轴和下游成片 | 不相干行的音频；不包含该行的 shots 和其它课程 |
| 单角色外观/服装参考 | 该角色 Bible/参考图、使用该角色的 Storyboard 片格/提示词/镜头及下游合成 | 其它角色镜头与所有 TTS；共享角色表变更则只重做引用该表的课次 |
| voice ID/语气 | 使用该 profile 的 TTS 行、受影响混音、字幕对轴（若时长改变）和成片 | 镜头视频、其他 profile 的 TTS |
| 单镜头动作/构图/prompt/reference | 该 shot 的新 prompt/参考图和视频任务、粗剪/最终成片 | 其它 shot、TTS、字幕时间轴 |
| 仅中文译文、英文字幕样式或 SRT 标点 | SRT/字幕 overlay、相关字幕检查和所有烧录该字幕的成片；软字幕轨重新封装 | TTS 与视频镜头 |
| TTS 时间、停顿或混音顺序调整 | 混音、受影响字幕时间码、合成/导出 | TTS 原始 WAV（若文本与单句音频未变）和视频镜头 |
| 横屏/竖屏画幅、标题文字、字幕卡/字号/颜色等版式 | 对应画布重新合成与媒体检查；字幕源时间轴/动画源未变时直接复用 | 通过验收的 TTS、镜头、横屏母版和 SRT |
| codec、分辨率、帧率、bitrate 等仅导出设置 | 受影响的最终合成输出及探测 | 文本、TTS、镜头和已核验时间轴 |
| 某供应商 job 下载/轮询失败，输入未变 | 用原 task/job ID 恢复、轮询或下载；记录错误与实际费用 | 不重新提交同一生成请求，不重跑同批其它节点 |

如果上游共享 profile 内容变化，列举并扫描所有引用它的 lesson/shot ID，只将这些消费者标为失效。不得因一课失败批量清空整批缓存，也不得把“文件存在”当作可复用；复用要求输入一致、输出可解码并通过相应审核。

## 6. 自动化、人工操作与成本边界

自动化负责重复且可验证的操作：按规范路径读写文件、dry-run 参数检查、行级 TTS/镜头调用、任务状态恢复、媒体探测、SHA-256、字幕/成片合成、更新 manifest。人工方便调整的边界是规范源文件：教材脚本、角色/视觉 profile、Storyboard/prompt、翻译/SRT、剪辑映射和验收结论。生成稿为这些文件的派生物，不反向覆盖源文件。

当前已有 TTS、视频生成和竖屏合成 CLI；本指南定义批次计划和增量重跑契约。仓库当前没有自动读取 `batch.yaml`、计算依赖失效并调度全批次的 runner。因此批次执行需要按本指南维护清单/看板并调用已存在 CLI；不能称为全自动调度已上线。若以后实现 runner，它必须支持 `plan/dry-run`、每个节点幂等、按失效图只执行后代、预算硬上限、逐节点日志和中断恢复，且由人工编辑的规范文件始终是事实来源。

成本控制规则：

- `batch.yaml` 必须设定批次及单课费用上限、最大并发数和允许 provider/model；费用未知的任务要先查报价/账单能力，不能把估算写成实际费用。
- 批量启动前对支持 dry-run 的待执行 TTS/视频节点先 dry-run，并人工汇总所有待执行节点的输入哈希、计划调用数、可复用项和报价/预计费用；无可靠报价时标“未知”并先确认费用边界。预算为空/不够时只继续零成本准备工作。
- 高费用供应商先做代表性样片；用户要求自动执行且已给出预算范围时可在预算内继续，不让 routine review 变成聊天确认门槛。
- 只对明确失败且确认供应商已终结/退款的任务创建新 job；轮询超时或临时网络错误使用原 ID 恢复，按 provider 技能规定的次数退避。禁止因 CLI 超时盲目重复提交。
- 一条 TTS 变更只重跑相应行。shot 变更只重跑对应镜头。导出或版式变更不触发任何计费语音/视频任务。

## 7. 批次完成条件

- 每课教材版本/范围、规范源文件和 unresolved 项明确；未核实内容未进入依赖它的生成。
- 每个输出均能回溯到 lesson/line/shot、源版本、参数/提示词、task ID 和 SHA-256；需计费节点有费用或未知原因及预算记录。
- 人工修改过的源文件已经递增版本；只失效并重跑依赖后代；其余素材复用证据可查。
- 所有计划课程完成技能与模板要求的媒体探测、抽帧/逐条检查和全片播放/试听；未完成者保持待验收或阻塞。
- 批次看板、所有课次 README、素材索引、GitHub Issue、提交和推送状态一致；报告已完成数、待验收/阻塞项、实际费用与交付位置。
